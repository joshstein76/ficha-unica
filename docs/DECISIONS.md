# LLAVE — decisions made while building (Josh delegated product/design calls, 2026-10-17)
Each line: the call, why, how to undo.

1. **Local stack = Python 3.9 stdlib + SQLite + Pillow, server-rendered HTML.** This Mac has no node and the brief said local only. A new Supabase project would mean a new account action. The schema is written to port 1:1 to Supabase Postgres (same family as Cerquito and RentaPóliza), which is the production target. Undo: none needed, port when we go live.
2. **Agent sites are rendered by LLAVE, not WordPress multisite.** One app renders every agent site straight from the listings database. That makes each site a thin layer over our data, the same thing EasyBroker sells. IDX Bloom's multisite is built for WordPress + MLS. We kept its Wix model (free subdomain first, own domain later) and its 3-design idea (Residencia / Ciudad / Costa ≈ Estate / Skyline / Coastal).
3. **One canonical home per listing.** A Bolsa share shows the listing on the sharer's site with the sharer's contact. The canonical points to the owner's page, and the sharer's sitemap leaves it out. This is the RentaPóliza 08-17 ruling and avoids the duplicate-content mistake we saw on EasyBroker agent sites.
4. **AI search built in:** RealEstateListing + Offer JSON-LD, plus `llms.txt` per site. It is the main edge over EasyBroker, whose agent sites ship no structured data (our 08-17 audit).
5. **Portals:** open formats first (Trovit / Mitula style, LLAVE open feed). Mercado Libre goes out as a dry-run payload, because the agent will connect their own account. Every other portal stays a stub that says it needs an agreement. The UI never claims a portal is live. The Trovit/Mitula formats are from public knowledge and marked "confirm with Lifull Connect".
6. **GHL dry-run only.** Each lead plans contact upsert + note + opportunity + agent alert into `outbox`. Nothing is ever addressed to the lead, because the first reply needs a template Josh approves. Live mode raises until a LLAVE sub-account exists (Q5).
7. **Photos:** we strip all EXIF (GPS is personal data), resize to 1600/800/400 in JPEG + WebP, and reject anything under 600 px or banner-shaped. Watermark is optional and OFF by default; we never add a watermark to someone else's photos. Floor plans under 600 px get rejected, so a plan exception is a later tweak.
8. **VIVE demo data:** only Heráclito 331 and Ritz 5203 are public (cleared). The other 6 Ritz units are `pausada`, with Josh's approval note kept internal. 5102 and 5002 have no price (marked "verify"). Only Heráclito is in the Bolsa.
9. **Plans in code:** gratis 10 listings / pro 50 / agencia 200. Matches proposal Q3-A; change `db.PLAN_LIMITS`.
10. **Privacy:** the lead form requires consent to a simplified notice. The notice is marked as a DRAFT for counsel (new 2025 data-protection law).
11. **Code name LLAVE** everywhere internal. The public brand waits for Q1 (Ficha Única / Inmo Abierta / Asesor Libre).

18. **First reply to leads (Josh tapped Approve, 10-17):** "Hola {nombre}, gracias por escribir sobre {propiedad}. Soy {asesor} de {inmobiliaria}. ¿Le comparto más fotos y detalles por aquí o prefiere agendar una visita?" The no-name variant is the same, starting "Hola, gracias por escribir…". Every agency starts with it and can edit it in Mi sitio, with placeholder checks and a live preview. {nombre} is only ever a real first name, never a handle, email, number or emoji. 19. **CSV photo import is SSRF-guarded.** We accept only http/https on ports 80/443, with no credentials in the URL. We block private, loopback, link-local and metadata addresses, numeric-host tricks, and our own domain. Every redirect is re-checked, and each request connects to the IP we already validated. Files must be JPEG/PNG/WebP (we check the real file signature) and ≤15 MB, with at most 20 per listing. Downloads run one at a time in a background worker. Live-tested on 10-17 against our own vivepolanco.mx photo: a real photo came in, 127.0.0.1 was blocked, and the logo was rejected as too small.
20. **Mercado Libre connection:** the agent connects their own account (OAuth with PKCE, single-use state that expires after 10 minutes). Real token exchange and publishing only run when the app is registered AND `LLAVE_ML_LIVE=1`; otherwise publishing goes to the outbox as a dry run. A "Ver demo" button shows the flow locally. Setup steps for later are in `docs/MERCADOLIBRE-SETUP.md`. Tokens go to Supabase Vault in production.
21. **Supabase draft** (`supabase/migrations/0001–0003`, not run anywhere): RLS on every table, leads only through the `submit_lead()` RPC, public views without the internal note or commission. A review fix: a trigger takes the share split from the listing owner and keeps `listing_id` immutable on shares.
22. **Mobile polish:** on listing pages, the price and key facts sit under the title, photos swipe, and a sticky WhatsApp / "Me interesa" bar stays at the bottom. In the panel, the setup checklist collapses once all 5 steps are done, there's a floating "+" for a new listing, and team accounts are greeted by agency name.
23. **First listing in 3 taps (`/nueva`)**: (1) photos + venta/renta + type, (2) price + colonia/alcaldía + m²/rooms, (3) review the suggested title and description, then "Publicar". Sign-up drops agents straight into it, and the "Publicada" screen has a "Compartir por WhatsApp" button. Free portal feeds are switched on by default with a visible checkbox. The full form and CSV import stay one link away.
24. **Bolsa filters + map:** filters for operation, type, minimum bedrooms, price min/max, currency and colonia. The map uses Leaflet + OpenStreetMap tiles. Pins snap to a ~250 m grid unless the owner chose to show the exact address, and listing pages show the same "ubicación aproximada" map. Agents set the pin by pasting a Google Maps link in the editor. Demo pins were geocoded once with OSM Nominatim (3 requests; Heráclito is street-level).
25. **Weekly price check:** listings whose price is over 30 days old or undated show a banner on Inicio and a `/precios` page with a one-tap "Sigue igual". `tools/price_check_weekly.py` queues one WhatsApp alert per agency per week, dry-run to the outbox, never to clients. No cron is created yet; it gets scheduled when production exists.
26. **Client inbox:** status filter tabs plus one-tap status buttons on each client. "Responder por WhatsApp" goes through `/clientes/<id>/whatsapp`, which records the first response, marks the client contacted, and opens WhatsApp with the agency's approved first reply. A red "⏰ sin respuesta · N min" badge shows after 5 minutes, along with a red banner on Inicio and in Clientes.
27. **5-minute reminder:** `tools/lead_watch_run.py` (meant to run every minute once production exists; nothing is scheduled) queues one WhatsApp reminder per unanswered client to the receiving agency, as a dry run. It never messages the client.
28. **Stats page** (`/estadisticas`): listing views (bots skipped, daily count, no personal data), clients per week, median response time, % answered in ≤5 min, sources and top colonias.
29. **Academia lesson 1 script** is in the lane (`work/2026-10-17-ACADEMIA-LECCION-1-GUION.md`). Josh approves the script and the cut before anything is recorded or published.
30. **Agent public profile** (`/asesor/<slug>`, set up in Mi perfil): photo (square, 400 px, metadata stripped), zones, bio, WhatsApp, the agent's listings, and RealEstateAgent JSON-LD. It's opt-in ("Mostrar mi perfil"). Own listings show the agent and link to the profile; shared Bolsa listings always show the sharing agency. Team logins ("Equipo …") show the agency name.
31. **Plan screens in TEST MODE** (`/plan`, `/plan/<key>`): Gratis / Pro MXN 299 / Agencia MXN 799, IVA included. Changing plan needs no payment and every change is audited as `plan_change_test_mode`. A downgrade is blocked if the agency has more listings than the new plan allows. Stripe (Ciao Bella Marketing) replaces the confirm step in production.
32. **Accessibility + speed pass** (from an audit of 25 findings, all applied):
    - Skip links, labelled forms, error association, contrast-safe accent and brand text (computed per accent), darker field borders, 20 px checkboxes, aria-current and labelled navs, accessible map region, fieldsets in the wizard.
    - WebP `<picture>` with srcset/sizes and width/height; the LCP image is fetchpriority high and the rest lazy.
    - gzip (home 13.4→4.7 KB, listing 20.4→6.8 KB), HTTP/1.1 keep-alive, immutable media caching with ETag/304, one display font per design.
33. **Referral loop** (`/invitar`): each agency gets a personal link (`/registro?ref=<slug>`), shared by WhatsApp or copied, and the site-footer "Ficha Única" link carries it through the landing page. **Reward: +5 listings per invited colleague who publishes their first listing**, permanent (`db.REFERRAL_BONUS_LISTINGS`). This is my call and costs us almost nothing; Josh can change or remove it.
34. **Instagram cards** per listing: post 1080×1350 and story 1080×1920 at `/propiedad/<slug>/tarjeta-post.jpg` / `tarjeta-historia.jpg`. They show the photo, a sale/rent pill, price, title, key facts, colonia, the price date, and the agency + WhatsApp in an accent footer. Cached, and rebuilt automatically when the listing changes. Links are in the listing editor and on the "¡Publicada!" screen. System Arial is used locally; production bundles Figtree. The printable A4 sheet (`/ficha`) stays as the flyer.
35. **Admin view** (`/admin`, role `admin` only, set with `tools/make_admin.py <email>`): totals, every unanswered client >5 min across all agencies, an agencies table (plan, public listings, clients in 30 days, at-risk count, who invited them, last activity), and outbox counts. Read-only. Client phones never appear in full (first name + listing only).
36. **Production readiness (nothing deployed):**
    - `LLAVE_ENV=production` switches links to https without a port, adds `Secure` to cookies, and sends HSTS and frame headers. The app refuses to start with a dev secret, a `.localhost` domain, or live GHL without Josh's recorded yes.
    - `/healthz` and `/_tls/ask` (on-demand certificates only for our hosts + verified custom domains, asked from localhost only).
    - Errors go to a rotating log plus rate-limited, redacted alerts (webhook/email, production only).
    - Backups are online SQLite copies with an integrity check, a checksum and gzip, plus incremental media; retention is 14 daily + 8 weekly.
    - Deploy kit in `deploy/`: the target (VPS or Cloud) is configurable, it's a dry run unless `target.env` + `--go`, and it does a backup, release symlink, health check and auto-rollback.
    - Recommendation: Hostinger VPS (wildcard + custom-domain TLS need root).

    - All subjects ≤ 40 characters, no emoji, ALL CAPS or "urgente/gratis/oferta" (`emails.check`). The sender name is the brand.
