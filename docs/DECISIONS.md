# LLAVE — decisions made while building (Josh delegated product/design calls, 2026-10-17)
Each line: the call, why, how to undo.

1. **Local stack = Python 3.9 stdlib + SQLite + Pillow, server-rendered HTML.** This Mac has no node and the brief said local only. A new Supabase project would mean a new account action. The schema is written to port 1:1 to Supabase Postgres (same family as Cerquito and RentaPóliza), which is the production target. Undo: none needed, port when we go live.
2. **Agent sites are rendered by LLAVE, not WordPress multisite.** One app renders every agent site straight from the listings database. That makes each site a thin layer over our data, the same thing the incumbents sell. IDX Bloom's multisite is built for WordPress + MLS. We kept its Wix model (free subdomain first, own domain later) and its 3-design idea (Residencia / Ciudad / Costa ≈ Estate / Skyline / Coastal).
3. **One canonical home per listing.** A Bolsa share shows the listing on the sharer's site with the sharer's contact. The canonical points to the owner's page, and the sharer's sitemap leaves it out. This is the RentaPóliza 08-17 ruling and avoids the duplicate-content mistake we saw on other platforms' agent sites.
4. **AI search built in:** RealEstateListing + Offer JSON-LD, plus `llms.txt` per site. It is the main edge over the incumbents, whose agent sites ship no structured data (our 08-17 audit).
5. **Portals:** open formats first (Trovit / Mitula style, LLAVE open feed). Mercado Libre goes out as a dry-run payload, because the agent will connect their own account. Every other portal stays a stub that says it needs an agreement. The UI never claims a portal is live. The Trovit/Mitula formats are from public knowledge and marked "confirm with Lifull Connect".
6. **GHL dry-run only.** Each lead plans contact upsert + note + opportunity + agent alert into `outbox`. Nothing is ever addressed to the lead, because the first reply needs a template Josh approves. Live mode raises until a LLAVE sub-account exists (Q5).
7. **Photos:** we strip all EXIF (GPS is personal data), resize to 1600/800/400 in JPEG + WebP, and reject anything under 600 px or banner-shaped. Watermark is optional and OFF by default; we never add a watermark to someone else's photos. Floor plans under 600 px get rejected, so a plan exception is a later tweak.
8. **VIVE demo data:** only Heráclito 331 and Ritz 5203 are public (cleared). The other 6 Ritz units are `pausada`, with Josh's approval note kept internal. 5102 and 5002 have no price (marked "verify"). Only Heráclito is in the Bolsa.
9. **Plans in code:** gratis 10 listings / pro 50 / agencia 200. Matches proposal Q3-A; change `db.PLAN_LIMITS`.
10. **Privacy:** the lead form requires consent to a simplified notice. The notice is marked as a DRAFT for counsel (new 2025 data-protection law).
11. **Code name LLAVE** everywhere internal. The public brand waits for Q1 (Ficha Única / Inmo Abierta / Asesor Libre).

50. **`llave/mailer.py`.** `send(con, to, subject, text, html=None, kind='')` over SMTP (`LLAVE_SMTP_HOST/PORT/USER/PASSWORD/FROM`, the same variables `alerts.py` uses for error emails; 587 STARTTLS, 465 SSL, 25 plain; certificates verified). No SMTP = the message becomes an outbox row `email.<kind>` with status `dry_run` and nothing leaves; with SMTP the row says `sent` or `error`. It never raises, and the password is never stored, printed or logged (errors are scrubbed). **An empty subject or body, a bad address or a line break in the subject is refused** (recorded as `error: rechazado`) — we once sent empty emails and that is a hard rule. From a web request on a file database, real SMTP goes out on a worker thread so a dead mail server never holds up a visitor; cron jobs send inline. Password-reset rows never keep the text (it holds the private link).

Adding the brand fonts later regenerates the cards by itself (the font files are part of the cache key). `LLAVE_CARD_FONT` still forces one font for all text. Not done: the licence text file for Figtree was not available offline, so the folder has a README with the copyright line and licence name; the upstream `OFL.txt` goes next to the fonts before they are redistributed. Downloading the two brand fonts needs the owner's yes.
    - **¡Vendida! / ¡Rentada! cards.** Real statuses only: `vendida` and `rentada` (`db.CLOSED_STATUSES`); asking for one on any other status raises. Text is only what is true: the stamp, the property type, the title, facts, colonia, "¿Quieres vender la tuya?" / "¿Quieres rentar la tuya?" and the agent's own name and number. **No price unless the agent ticks "Mostrar el precio de lista" (off by default)**, and then it is labelled "Precio de lista", never "vendida en", because nothing records what it sold for. No buyer, deal amount, street or days on market, ever (the card does not read the deals table). A title that states a price (a currency sign or word, "mdp", "millones", a 5-digit number, or the price's own digits) is replaced by "{Tipo} en {colonia}" while the price is hidden. The card has no public URL: it is made in the panel, `GET /propiedades/<id>/cierre-post.jpg` and `cierre-historia.jpg` (`?precio=1` to show the price), for the agency's own sold or rented listings, `Cache-Control: private, no-cache`. The cached file lives in `media/cards/` (skipped by the backup) under a name with a 64-bit hash of the card's content, and only holds what the agent chose to show.
    - **Plans: unchanged.** Every card (post, story, ¡Vendida!) stays in the `tools` feature, Pro and up. With `LLAVE_PLANS_V2=1`, Gratis also gets the plain post card (`cards.can_make`), never the story and never ¡Vendida!. The 1200x630 link-preview card and the wa.me share are for every plan (they are the preview of a public page, not an Instagram tool). **Recommendation: turn that on for Gratis.** The post card is the one an agent forwards to groups, it carries our line, and the cost is one 0.3 s render per change; Pro keeps story, ¡Vendida! and the printable sheet.
    - **Attribution.** "Hecho con Ficha Única · fichaunica.mx" on an ink pill under every card, always. No removal option exists today (agent sites already carry "Sitio creado con Ficha Única" on every plan), so none was added.
    - **Phone and address.** The only number on a card is the listing agent's own WhatsApp (the agency's when the agent has none); never a street or number, only colonia and municipio.
    - **Cache.** `cards.render_cached` names each file by a hash of everything the card shows, the listing's `updated_at`, the font files and `CARD_VERSION` (bump it when the drawing changes); a changed listing, agent, colour or photo makes a new file and deletes the old one, written atomically. Found: the card routes sent `Cache-Control: immutable` for a year at a URL whose picture changes, so a browser or WhatsApp kept the old card after an edit. Card URLs now send `public, max-age=300` with the ETag of the current file (a 304 while nothing changed). Content-hashed `/media/...` files keep the year.
    - **Panel.** On a listing, a "Compártela" box: **Mándalo a tus grupos** (`https://wa.me/?text=`, no phone number: the title, price and colonia, then "Fotos y datos aquí: <url>"), "Tarjeta para publicar" and "Tarjeta para historia" for the plans that have them, and a note pointing to Pro for the rest. A listing the plan hides from the site shows no buttons (the card routes would 404). For a sold or rented listing the box is "¡Presume tu cierre!". The publish screen uses the same message and gate. The old small "Tarjeta Instagram / Historia" links in the header row moved into the box.
    - **Link preview.** The public listing page's `og:image` was the 1600 px photo (or an empty tag with no photo). Now the 800 px photo (a 1600 px file can be heavy enough that WhatsApp skips it; not measured here) with `og:image:width/height/alt`, `twitter:card`, and `og:site_name`; with no photo, the lotería link card `/propiedad/<slug>/tarjeta-enlace.jpg`; and a description made from price, facts and colonia when the agent wrote none.
    - **Not checked.** The real Shrikhand and Bricolage files (not on hand; the lookup and layout were exercised with stand-in files), how WhatsApp itself renders the preview, and the card on a physical phone.
